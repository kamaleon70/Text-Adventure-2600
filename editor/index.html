Author's guide

User manual

Everything needed to create, test, save, and build a text adventure inside this browser editor.

Recommended workflow

Start your adventure

  1. Use World map to create the locations in the game.
  2. Open Rooms & scenes to write text and connect locations.
  3. Add state in Flags & variants and portable items in Objects.
  4. Exercise every route in Playtest.
  5. Use Save config regularly, then build the finished cartridge from Build & run.

The editor keeps a browser-local draft after changes. This protects against an accidental refresh, but browser data can be cleared, so it is not a replacement for downloaded backups.

Your project file

Save and restore

  • Save config downloads the complete editable adventure: rooms, scenes, text, links, flags, objects, contextual actions, and splash settings.
  • Load config replaces the current editor contents with a previously saved configuration.
  • Save numbered backups at important milestones and keep them somewhere outside the browser.
  • Loading a configuration does not load a ROM; use the Build tab afterward to create a new cartridge.

World structure

World map

  • Add room creates a location with one primary scene.
  • Drag room cards to arrange the diagram. Position changes only the editor map; it does not change gameplay.
  • Lines show NORTH, EAST, SOUTH, and WEST connections configured for each room.
  • The star identifies the start room. Double-click a room to open its primary scene, or click it once to select it.
  • The 32K F4 layout supports up to 102 scenes and 12,240 fixed text characters.

Locations and text

Rooms and scenes

  • A room is a logical location. Its four exits are shared by its scenes unless a scene explicitly overrides one.
  • A scene is one Atari text screen: ten rows of up to 12 characters. Text is converted to uppercase and the eleventh action row is controlled by the game engine.
  • Set start room chooses where a new game begins. Make primary chooses which scene appears when the player enters that room.
  • Room names must be unique. Scene names must be unique inside their room; internal IDs are created automatically.
  • Add scene creates another page inside the same room. Earlier/Later changes its authoring order.

Multiple pages

NEXT and movement overrides

  • NEXT links to another scene in the same room. Choose End continuation when there is no next page.
  • NEXT chains should finish rather than loop; the editor warns about continuation cycles.
  • Movement normally uses the room's exits. Open Optional movement overrides only when this particular scene needs a different destination or no exit.
  • LOOK returns to the room description currently selected by its variant rules.
  • Entering a room through movement always resolves its primary or conditional scene, not an arbitrary continuation page.

Winning and losing

Ending scenes

  • Write the congratulation, victory, game-over, or other ending message as an ordinary scene.
  • Enable Ending scene — only Restart is available for that scene. On the Atari, its action row becomes FIRE:RESTART; movement, inventory, NEXT, and contextual actions are disabled.
  • Pressing Fire restores the initial flags and object locations, then returns to the configured start room.
  • For a conditional ending, add the ending scene to a room and select it in a Room description variant. Set the required flags on that variant. When the player enters the room with those conditions satisfied, the ending scene is shown.

Persistent story state

Flags and room variants

  • A flag records a yes/no fact such as door_open or power_on. Up to 64 flags are available.
  • Initially set controls the flag's value when a new game starts.
  • A room variant redirects the room description to another scene when all selected must be set flags are on and all must be clear flags are off.
  • Variant rules are checked from top to bottom; the first match wins. If none matches, the primary scene is used.
  • For multi-select fields, use Ctrl-click on Windows/Linux or Command-click on macOS to select more than one flag.

Built-in actions

Scene action effects

Select a scene and one built-in action: LOOK, NORTH, EAST, SOUTH, WEST, or NEXT. Then choose flags to modify before that action follows its link.

  • SET turns a flag on.
  • CLEAR turns a flag off.
  • TOGGLE reverses its current value.
  • A flag can have only one operation for the same action. Effects still run when an action has no destination.

Example: NORTH can SET door_seen; a later room variant can display a new description when that flag is set.

Inventory

Objects

  • Up to eight objects are supported; each consumes one byte of Atari RAM.
  • Object ID is the unique internal name. Inventory name is the uppercase label shown to the player and is limited to 12 characters.
  • Initial location can be a room, Carried initially, or Removed initially.
  • An object in a room can satisfy a contextual action's Must be here requirement. A carried object can satisfy Must be carried.
  • An object cannot be deleted while a contextual action still refers to it.

Custom verbs

Contextual actions

  • Choose a scene and click Add action. Its cartridge label is the verb shown on the Atari action row, up to 12 characters.
  • Require set/clear, Must be carried, and Must be here determine when the action is offered.
  • The action can SET, CLEAR, or TOGGLE flags, Take object into inventory, and/or Remove object from play.
  • After the action runs, the current room's variant rules are evaluated again, allowing the displayed description to change immediately.

Example: TAKE KEY requires the key to be here and takes it. UNLOCK requires the key to be carried, sets door_open, and can remove the key if it is consumed.

Fast iteration

Playtest

  • Use the action buttons to test movement, NEXT chains, inventory, and contextual actions without building a ROM.
  • Reset to start room restores every flag and object to its configured initial state.
  • The Flag debugger can force flags on or off to inspect room variants.
  • The Object debugger can move an item among rooms, inventory, and removed state to test requirements.
  • Test both successful and unavailable actions, every room entry, and every conditional description before building.

Cartridge display

Colours and border

  • Select separate Atari colours for the centre story background, side panels, story text, and action-row text.
  • Striped side panels preserves the original look. Solid side panels fills both sides with the selected panel colour, as shown in the preview.
  • The optional action-row background changes only the centre area behind the final line; the side panels continue beside it.
  • Create reusable presets such as Outdoor, Castle, or Dungeon, then select one from a room's Room appearance list.
  • Selecting a room appearance applies it to every scene in the room and clears its previous scene overrides. You can then customize individual scenes again if needed.
  • Individual scenes can inherit the room appearance, override selected settings, or copy another scene.
  • The inheritance order is Global default → Room appearance → Scene override.
  • The browser preview approximates NTSC colours. Test the finished ROM in Javatari or Stella before publishing.

Opening artwork

Create a splash screen

  1. Open Atari Background Builder.
  2. Draw the 40-pixel-wide image and select black ($00) for the background colour.
  3. Set Render Type to ASM Asymmetrical (Mirrored) color.
  4. Set Kernel to 2 Scanline Kernel.
  5. Use a height from 1 to 90 rows, which produces up to 180 scanlines.
  6. Export/download the ASM, return to this editor's Splash screen tab, and upload that .asm file.
  7. Enable Use splash screen in ROM, inspect the preview, and choose the minimum display time.

120 frames is about two seconds on NTSC. After the delay, the player must release Fire and press it again. Physical bank 0 is always the startup bank, so enabling artwork does not reduce the 102-scene capacity.

Cartridge workflow

Build and run

  • Build & download assembles the current editor contents and downloads a 32K F4 cartridge ROM.
  • Build & run Javatari assembles the same ROM and starts it in the embedded emulator.
  • The Build output reports progress or identifies invalid configuration and assembly errors.
  • The Debug tab shows the splash, shared logic, and automatic scene-bank allocation.

Atari controls

Playing the cartridge

  • Joystick directions attempt NORTH, EAST, SOUTH, or WEST.
  • Fire enters action-selection mode.
  • Move the joystick while selecting to cycle through LOOK, NEXT, INVENTORY, and available contextual actions.
  • Press Fire to perform the selected action.
  • Release the joystick and Fire between inputs so each press is detected cleanly.
